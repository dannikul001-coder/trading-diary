# Trading Diary

Русскоязычный single-page торговый дневник на HTML/CSS/JavaScript.

## Что реализовано

- пустая таблица при первом запуске;
- добавление, редактирование и удаление сделок;
- Win / Loss / Draw;
- формула P&L: Win = stake × payout / 100, Loss = −stake, Draw = 0;
- автоматический баланс от стартового баланса;
- дневная, недельная и месячная статистика;
- Win rate, средний P&L, прибыль, убыток, payout, серии Win/Loss;
- поиск, фильтры и сортировка сделок;
- графики баланса и P&L на Chart.js;
- психология на основании состояния сделок;
- план, заметки и цели;
- Forex, Crypto, Commodities, Indices, Stocks, OTC и Custom;
- добавление собственных инструментов и стратегий через настройки;
- много валют и часовых поясов через IANA/Intl браузера;
- JSON/CSV экспорт и импорт;
- PWA service worker;
- архитектурный слой storage, который можно заменить на облачное хранилище.

## Запуск

Для основной функциональности можно открыть `index.html` напрямую. Для PWA/service worker нужен `localhost` или HTTPS.

Простой локальный сервер:

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080`.

## Данные

Сейчас данные хранятся в `localStorage` конкретного браузера. Это значит, что два человека на опубликованной странице не увидят данные друг друга, но и синхронизации между устройствами нет.

Для настоящей многопользовательской версии следует подключить Auth + PostgreSQL/Supabase. Каждая таблица должна содержать `user_id`, а правила доступа — разрешать пользователю читать и изменять только собственные записи.

Рекомендуемая будущая схема:

- users / auth;
- trades;
- notes;
- plans;
- goals;
- journals;
- instruments;
- user_settings.

Интерфейс уже отделён от хранения через `storage.js`, поэтому переход на облачное хранилище не требует переписывания всего UI.

## Pocket Option CSV

CSV-импорт сделан с распознаванием распространённых названий колонок и предварительным преобразованием результата. Точный формат экспорта Pocket Option нельзя гарантировать без конкретного CSV-файла: перед production-импортом рекомендуется протестировать реальный файл пользователя.

## Важно

Это дневник/аналитика, а не торговый сигнал или финансовая рекомендация. P&L рассчитывается только из введённых пользователем данных.

## v3: аккаунты и облачная синхронизация

В проект добавлены UI для входа/регистрации и SQL-схема Supabase. Для реальной облачной работы:
1. Создайте проект Supabase.
2. Включите Email/Password Auth.
3. Выполните `supabase/schema.sql` в SQL Editor.
4. Вставьте Project URL и publishable/anon key в `js/supabase-config.js`.
5. Опубликуйте приложение по HTTPS.

Не помещайте `service_role`/secret key во frontend. Доступ к строкам таблиц ограничивается RLS по `auth.uid()`. См. официальную документацию Supabase Auth и RLS.

Если Supabase не настроен, приложение продолжает работать в гостевом локальном режиме.
