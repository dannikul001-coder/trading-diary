# Trading Diary 02 — V5.1: исправление регрессий после V4

**Дата:** 31 октября 2026 г.  
**Тип:** исправление ошибок второго дневника + уточнение календаря, аналитики и обзора.  
**База:** `trading-diary-automated-workspace-v4-20261030.zip`.

## Почему не работали три кнопки «Добавить»

Функции `showTradeForm(editId)`, `showBonusForm(editId)` и `showSignalForm(editId)` принимали на вход *идентификатор редактируемой записи*. В V4 обработчики были подключены напрямую через `addEventListener('click', showTradeForm)`, из-за чего браузер автоматически передавал в качестве первого аргумента объект `MouseEvent`. Функции воспринимали его как `editId` и не открывали пустую форму.

**Исправление:** вызов через функции без аргументов `()=>showTradeForm()` и аналогичные для бонусов и сигналов.

## Почему показывалось меню основного дневника

Второй дневник использовал `data-edit-trade`, совпадающий с делегированным обработчиком основного приложения в `js/app.js`. Событие всплывало до `document`, где открывалось чужое окно. **Исправление:** атрибут второго дневника переименован в `data-ad-edit-trade`; его обработчик привязан внутри второго дневника, а корневой контейнер останавливает всплытие кликов в обработчики основного. Также изолирован чекбокс плана `data-ad-toggle-plan`.

## Что изменилось для пользователя

- **Сделки:** вновь открывается форма создания. Редактирование остаётся в дневнике 02, не вызывает модальное окно основного дневника. Кнопка закрытия динамических форм работает после создания формы.
- **Бонусные мешочки:** кнопка добавления открывает новую форму, а редактирование продолжает работать.
- **Расписание:** кнопка добавления открывает новую форму. Проверено отображение восьми отдельных сигналов за выбранный день; редактирование доступно отдельно для каждого.
- **Календарь:** прибыльные дни (сумма `пayout − stake` закрытых за дату сделок строго больше нуля) выделяются зелёным; текущий день обозначен отдельно. Дни недели выровнены по колонкам с понедельника. Отображается краткая сводка по месяцу.
- **Аналитика:** непонятные диаграммы заменены на две проверяемые таблицы: количество закрытых сделок и суммарный доход по диапазонам времени и дням недели. В каждом разделе указано, что группировка выполняется **по времени закрытия сделки** в часовом поясе пользователя, за выбранный период (не только за одну неделю). Формула дохода: полный возврат минус ставка; переводы и бонусы исключены.
- **Обзор:** добавлены быстрые карточки плана, целей, последних заметок и восьми сигналов на сегодня, рассчитанные только по собственным записям второго дневника. Разделы можно открыть с карточек.
- **Обновление PWA:** изменено имя кеша Service Worker, чтобы новая сборка не подменялась старым JavaScript из офлайн-кеша.

## Какие файлы изменены относительно V4

- `js/automated-diary.js` — обработчики создания/редактирования и интерфейс.
- `automated-diary.css` — выделение дней, карточки и таблицы.
- `index.html` — только надпись `V5.1` в шапке второго дневника.
- `sw.js` — версия кеша.
- `tests/automated_v4_finance.cjs` — адаптация регрессионных проверок под новое имя атрибута и проверка нового содержимого.

**Не изменены:** код `js/app.js` / `js/admin.js` основного дневника, формула P&L основного дневника, существующие SQL-миграции, RLS, данные пользователей, настройки реального Supabase и почтовая Edge Function.

## Как обновить опубликованный сайт

1. **Сохранить резервную копию** текущего V4 ZIP/репозитория и базы Supabase. Не удалять ни одного пользовательского раздела, таблицы или сделки.
2. Распаковать V5.1 и заменить **файлы сайта** файлами из папки `Новинка`, сохранив уже созданные настройки проекта, если они отличаются. Важен новый `js/automated-diary.js`, `automated-diary.css`, `index.html` и `sw.js` — их нужно публиковать вместе.
3. Дождаться публикации GitHub Pages и сделать полную перезагрузку страницы (Ctrl+Shift+R). Для установленного PWA иногда нужно закрыть/переоткрыть приложение или обновить его кеш.
4. В шапке второго дневника появится `РАБОЧЕЕ ПРОСТРАНСТВО / 02 · V5.1`. Если этого текста нет, браузер или GitHub Pages продолжает отдавать старую версию.
5. Проверить под **своим тестовым аккаунтом** создание и изменение сделки, мешочка и сигнала. Сверить баланс до и после. На основном дневнике убедиться, что сделки и синхронизация работают как раньше.

### SQL

**В V5.1 нет новых SQL-файлов и нет необходимости повторно выполнять миграцию V4.** Создание/изменение сделки и бонуса вызывает уже предусмотренные функции `ad_open_trade_v2`, `ad_edit_trade_v4`, `ad_save_bonus_v4`. Если SQL V4 не был установлен, сайт может вывести `PGRST202` / сообщение об отсутствующей RPC. В этом случае сначала проверьте состояние Supabase и резервную копию; не запускайте старые миграции наугад.

## Если запись по-прежнему не создаётся

- Убедитесь, что в интерфейсе действительно показано `V5.1`.
- Сохраните точный текст уведомления об ошибке. Например, отсутствие `ad_open_trade_v2` означает SQL-проблему, а не проблему кнопки.
- Проверьте, что ваш пользователь действительно вошёл в аккаунт и имеет собственный профиль второго дневника.
- Не переустанавливайте Supabase и не очищайте таблицы: такой способ «исправления» опасен для реальных данных.
